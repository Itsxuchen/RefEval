# Pre-outcome correction to the source-text check

The first frozen loader stopped during metadata preflight before it called the development or held value decoder. The cause was a character-encoding difference between the two original publications' JSON releases. Exact Unicode strings matched on 1,072 of 1,600 article records, 1,488 reference summaries and 1,528 candidate summaries. Rendering the UniEval UTF-8 bytes as Windows-1252 characters, preserving undefined bytes as their original control characters, reproduces all 1,600 G-Eval strings in each field. The original expert summaries match the UniEval summaries on all 1,600 output keys after case, punctuation, tokenized bracket and spacing normalization. G-Eval's stored strings can contain visibly garbled punctuation or accents. This may have influenced the archived model responses.

The replacement loader enforces this exact encoding relation on all three text fields across all four G-Eval files. Original and superseding freeze digests are retained. All splits, scores, cutoffs, exclusions and analysis rules remain as recorded before the failed preflight. The labels were still masked when this correction was made.
